# 剧抛大脑：英语生存局

> 把背单词变成演剧情。五个剧本、1000 道剧情化词汇题，答对一题，小说剧情就往前一步。

**在线体验：** <https://chy060.github.io/jupao-english/>

纯前端静态站，无需登录、无需后端，手机与电脑浏览器直接打开即可游玩。

***

## 一、这是什么

一个把「英语词汇学习」嵌进「追剧式剧情」的互动小游戏。

用户不是在选词义，而是在替剧中角色说出那句该说的话：每道题先给场景设定和剧情描述，再给一句英文原声台词，然后要求从三个回复里选出符合剧情、且用对了目标词的那一句。答对推进剧情，答错给出中文逻辑解析。

答题进度同时驱动奖励小说解锁——每答对 4 题，解锁 1 章原创小说。

## 二、核心功能

| 功能          | 说明                                              |
| ----------- | ----------------------------------------------- |
| 五套剧情剧本      | 大女主 / 大男主 / 百合 / 耽美 / 纯爱，各自独立的场景、人设、台词风格        |
| 1000 道剧情化题目 | 每个版本 50 章 × 4 题 = 200 题，五版共 1000 题              |
| 四段式题目结构     | 场景设定 → 剧情描述 → 英文原声 → 提问 + 三个选项                  |
| 单正确项设计      | 三个选项只有一个包含目标词，其余是「符合剧情但用词不对」的干扰项                |
| 五版词序错开      | 200 个词在每个剧本中按不同起点轮转出题，同一章在不同剧本里考的词不同            |
| 答错解析        | 正确答案标绿，并给出中文逻辑解析，说明为什么这句只能用这个词                  |
| 全文朗读        | 台词与每个选项都可点读（Web Speech API，无需外链音频）              |
| 奖励小说        | 每个版本 2 本原创同题材小说，各 50 章，共 10 本 500 章             |
| 进度绑定解锁      | 每答对 4 题解锁 1 章，每题推进 0.5%，两本同步推进                  |
| 数值与风险       | 气血、金币、复活、章节过关，答题有成本                             |
| 分版本独立存档     | localStorage 按剧本 ID 分档，切换剧本互不覆盖，刷新可续            |
| 单词本         | 只收录已答过的词，按表现自动标色：一直答对为绿、答错过为黄、从没答对为红，附中文释义与对错次数 |
| 个人中心        | 昵称、内置头像、自定义头像上传、进度总览、清除数据                       |
| 问题反馈        | 填写内容 → 调起邮件客户端并自动附带排查信息，同时复制到剪贴板兜底              |

## 三、玩法与数值

| 项目   | 规则                                   |
| ---- | ------------------------------------ |
| 初始气血 | 100%                                 |
| 答对   | +10 金币，气血 +5（上限 100）                 |
| 答错   | 气血 -10                               |
| 章节过关 | 每章 4 题，答对 ≥3 题即过关并解锁下一章              |
| 气血归零 | 进入结算，可花 100 金币复活                     |
| 奖励解锁 | 每个版本 200 题 ÷ 每本 50 章 = 每答对 4 题解锁 1 章 |

## 五、技术栈

- 原生 HTML / CSS / JavaScript，无框架、无构建步骤、无依赖

- 模块以 IIFE 形式挂载到 `window`，分层为：数据层 → 工具层 → 逻辑层（游戏引擎）→ UI 层

- 语音：优先 `window.speechSynthesis`（Web Speech API）；本机没有英语语音或合成无响应时，自动回退到在线词典音频，保证点了有声音

- 存储：`localStorage`，键位 `jupao.saves.v1`（按版本分档）、`jupao.last.v1`、`jupao.profile.v1`、`jupao.album.consent.v1`、`jupao.wordstats.v1`（单词本答对/答错计数）

- 自定义头像：`FileReader` + `Canvas` 居中裁剪、压缩至 240×240 JPEG，全程在本地完成，不上传服务器

- 部署：GitHub Pages 静态托管

## 六、目录结构

```
index.html                  入口，按顺序加载数据层与逻辑层脚本
css/style.css               全部样式（暗色剧情主题、题目卡、章节网格、个人中心）
js/
  game.js                   游戏引擎（章节模式 / 词汇模式双模式状态机、数值、存档序列化）
  ui.js                     全部页面渲染与交互（版本选择、答题、奖励、单词本、个人中心、反馈）
  storage.js                本地存储封装（存档、资料、相册授权、单词本统计、清除数据）
  tts.js                    朗读封装
  shuffle.js                洗牌工具
  questionGenerator.js      词汇模式的题目生成器（兜底路径）
  data/
    versions.js             五个版本的定义（名称、配色、气质）
    words.js                200 个欧美剧高频词词库
    templates.js            词汇模式的剧情模板
    chapters.js             版本头像配置 + NOVEL_CHAPTERS 容器
    questions_*.js          五个版本的题库（各 50 章 / 200 题）
    rewards_*.js            五个版本的奖励小说（各 2 本 × 50 章）
    novels.js               词汇模式的旧版小说数据
assets/avatars/             版本头像与可选头像资源
server.ps1                  本地静态服务器（PowerShell，无需 Node）
deliverables/               参赛相关材料
```

## 七、本地运行

环境里不需要 Node / Python，Windows 自带 PowerShell 即可：

```powershell
powershell -ExecutionPolicy Bypass -File .\server.ps1
```

然后浏览器打开 `http://localhost:8765/`。

## 八、扩展一个新版本

1. 在 `js/data/versions.js` 增加版本定义（id、名称、颜色、气质）
2. 在 `js/data/chapters.js` 的 `VERSION_AVATARS` 增加头像映射
3. 新建 `js/data/questions_<id>.js`，写入 50 章 × 4 题，挂到 `window.NOVEL_CHAPTERS.<id>`
4. 新建 `js/data/rewards_<id>.js`，写入 2 本 × 50 章，挂到 `window.REWARD_NOVELS.<id>`
5. 在 `index.html` 中按顺序引入这两个文件

数据结构与主逻辑完全分离，新增剧本不改动引擎。

## 九、已知限制

- 纯静态站无后端，问题反馈依赖用户设备已配置邮箱客户端（已提供剪贴板兜底）

- 数据与存档均保存在浏览器本地，清除浏览器数据会清空进度

- 语音朗读的音色与可用性取决于浏览器与系统

- 首次加载需下载约 5.7 MB 题库数据，弱网环境首屏稍慢
